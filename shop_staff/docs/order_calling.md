# 将订单推送给叫号系统

入口：系统设置 → 打印机设置后面的「订单推送」→ 二级页面。

默认关闭。IP 地址和端口号在同一行的两个独立输入区域中填写：

- IP 地址：例如 `192.168.1.20`，只填写 IP，不填写协议、端口或路径。
- 端口号：默认 `3000`，可以修改；留空也使用 `3000`。

程序内部补齐请求地址 `http://{IP}:{端口}/api/add/order`。原来保存的组合地址会迁移为独立 IP 和端口。

## 推送范围

参考 Foodorder_WP `settlement_controller_printer_extension.dart::printData` 向 `_sendToDisplayPanel(data)` 传递的订单数据格式，使用 `POST /api/add/order` 发送 JSON。

- 本机成功下单的订单：普通下单及线下／记账下单。
- SSE 收到的订单：仅 `message` 的新订单 data，保留原始商品、选项、数量、备注、单号等字段。

按本项目的明确需求，不推送 `rePrint`、`payment_Completed`、`item_cancel`、心跳、桌位单或效期标签。此前队列中尚未发送的非订单通知标为 ignored，不恢复发送，也不能手动重试；已发生的历史发送记录保留在存储中，设置页仅显示订单记录。

推送独立于打印机配置与打印结果，不以打印成功为前提。网络客户端不携带云端 Authorization，不触发云端登录刷新，不自动重试 POST。

## 本机订单字段

保留后端下单响应中的信息，并补充商品、数量、选项、价格、备注、机号及订单 ID。

后端响应带 printInfo 时，优先保留其中的 UUID、单号和 orderLinesMap；否则用购物车生成票据结构，orderLinesMap 的 0 分组表示未取得后端打印路由的本机商品，仅供订单推送使用。

单号优先使用后端返回的 order_sn_code／orderSnCode／serialNumberText／serialNumber／serialNo，缺失时使用订单 ID；不额外调用打印接口。实际取餐单号仍需与叫号系统联调确认。

没有后端 UUID 的本机订单使用 `shopstaff:{machineCode}:{orderId}`，同一 UUID 的重复新订单推送去重。不同终端或本机与 SSE 使用不同 UUID 时，叫号系统仍需依其业务合同处理幂等。

## 队列与异常

配置存入安全存储，订单任务按 ID 写入 Hive 并 flush，网络发送在独立串行队列执行，不等待叫号系统响应后才完成收银。

关闭后不接收新任务、不启动后续发送；已发出的请求可能已经到达系统。待推送订单保留，重新开启后继续。

每条新任务记录入队时的目标地址；修改设置后，新订单使用新的 IP 和端口，历史任务仍保留原目标。手动重试明确使用当前保存的 IP 和端口。

HTTP 成功且没有明确业务错误才标为已推送。超时或失败保留记录，不阻挡其他订单。结果未确认时不会自动重发；在页面核对订单后可以手动重试，保留相同 UUID。应用发送中退出，重启后标为结果未确认。

最多保留 500 条记录，只淘汰已推送或已忽略的记录，不静默删除失败订单。页面展示最近 100 条订单记录。

iPad 使用本地网络权限和 NSAllowsLocalNetworking；Android 允许配置的局域网 HTTP 请求。真实叫号系统的响应、取餐单号、商品显示及幂等仍需连接真实系统验证。
